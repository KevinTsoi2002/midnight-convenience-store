# 《凌晨 2:17 的便利店》反馈层与饰品系统补全规格

**日期：** 2026-10-09  
**状态：** 用户已确认方向，待规格复核后实现  
**范围：** 仅补全现有单 HTML 游戏的反馈层与饰品交互，不改变离线交付形式

## 1. 问题定义

当前 Roguelite 版本已经具备三日流程、每日结算、饰品候选和评分规则，但两个核心体验仍不完整：

1. 便利店画面下方的文字只承担场景说明，不能连续表达顾客线索、商品覆盖、评分反馈和饰品生效结果。
2. 饰品目前是“选择后自动进入背包并自动装备”，没有完整的装备、卸下、替换、放弃和协同反馈。

本次补全的目标是让玩家在每轮都能回答两个问题：

- 我为什么得到这个分数？
- 我现在的三件饰品构筑，下一轮应该怎么用？

## 2. 核心体验方案

### 2.1 夜班对话栏

将便利店画面下方的 `scene-caption` 升级为固定的“夜班对话栏”，仍然保持当前视觉语言和单栏布局，不新增嵌套卡片。

对话栏按游戏状态展示不同信息：

| 状态 | 展示内容 |
|---|---|
| 顾客进入 | 顾客姓名、身份、当前台词、观察线索、今晚事件影响 |
| 选择商品 | 已装入商品、覆盖标签、尚未覆盖的显性需求 |
| 装袋反馈 | 顾客回应、命中的显性需求、隐藏需求结果、本轮分数、连击变化 |
| 饰品生效 | 生效饰品名称、触发条件、产生的加成或容错 |
| 第 2/3 天 | 隐藏线索直接进入对话栏；第 3 天减少直白措辞但不隐藏必要信息 |

对话栏必须做到：

- 每轮有可读的动态内容，不使用同一句泛化文案覆盖所有顾客。
- 商品选择变化时立即更新，不需要提交后才知道标签覆盖情况。
- 提交后保留反馈，直到玩家点击“继续”。
- 文字在 320px、390px 宽度下换行，不遮挡商品和按钮。
- 顾客回应、评分和饰品触发信息使用不同的视觉层级，但不能仅靠颜色表达。

### 2.2 值班抽屉

将当前饰品三选一页面升级为“值班抽屉”流程。候选页、背包页和装备页在同一覆盖层内完成，避免新增页面跳转。

候选卡必须显示：

- 中文品质：普通、稀有、史诗、传说。
- 饰品名称、短描述、标签。
- 明确的触发条件和效果。
- 与当前装备的协同提示，例如“与暖黄灯泡组成温暖构筑”。
- 当前状态：候选、已拥有、已装备或不可重复获得。

选择候选后进入操作确认：

- **装备：** 放入背包并占用一个装备槽。
- **放入背包：** 放入背包但不改变当前装备。
- **放弃：** 不加入本局，直接进入下一天或结局。

装备结构保持：背包最多 8 件，同时最多装备 3 件。同一饰品不能重复拥有。装备满时显示替换列表：

1. 选择一个当前装备的饰品。
2. 预览“卸下旧饰品 / 装备新饰品”后的协同变化。
3. 确认替换，或返回候选操作。

背包页提供：

- 已拥有饰品列表。
- “已装备 / 背包”状态。
- 点击已装备饰品可卸下。
- 点击背包饰品可装备；装备满时进入替换流程。
- 当前装备协同摘要。

## 3. 规则与数据流

### 3.1 对话栏数据

新增纯函数：

```js
getRoundDialogue(state, customer, selectedIds, scoreResult)
getCoveredTags(selectedIds)
getUncoveredNeeds(customer, selectedIds, day)
getTrinketTriggerSummary(scoreResult, equippedTrinkets)
```

`scoreSelection()` 继续负责纯评分，不直接修改 DOM。渲染层根据评分结果和当前选择生成对话栏内容。

每轮结果增加以下字段：

```js
{
  coveredTags,
  visibleNeedHits,
  hiddenNeedHit,
  score,
  streak,
  triggeredTrinkets,
  triggeredSynergies
}
```

### 3.2 饰品交互状态

新增状态字段：

```js
{
  trinketDraftId: null,
  trinketAction: null,
  replacingTrinketId: null,
  trinketNotice: null
}
```

统一通过纯规则函数处理：

```js
getTrinketById(id)
getEquippedTrinkets(state)
getStoredTrinkets(state)
getSynergySummary(state)
canEquipTrinket(state, trinketId)
applyTrinketAction(state, { trinketId, action, replaceId })
```

`applyTrinketAction()` 必须返回新的状态结果或明确的失败原因，不通过 `confirm()` 阻塞浏览器。

### 3.3 协同效果

保留三组协同并在 UI 中可见：

- `warmth + comfort`：本轮低分容错一次。
- `clarity + company`：隐藏需求命中时额外增加线索反馈。
- `risk + energy`：高分额外加成，同时低分会标记为“波动”。

协同只在两件或以上相关饰品真正装备时触发；仅拥有但未装备不触发。

## 4. 界面结构

### 4.1 游戏画面

在场景 SVG 下方保留一条不嵌套卡片的对话栏，结构语义如下：

```html
<section class="night-dialogue" data-night-dialogue aria-live="polite">
  <div data-dialogue-kicker></div>
  <p data-dialogue-main></p>
  <div data-dialogue-details></div>
</section>
```

对话栏与商品区保持视觉分隔，反馈状态需要稳定高度，避免点击商品后页面跳动。

### 4.2 饰品覆盖层

覆盖层内部使用三个明确区域：

```html
<section data-trinket-reward>
  <div data-trinket-candidates></div>
  <div data-trinket-drawer></div>
  <div data-trinket-action-panel></div>
</section>
```

候选卡是可聚焦按钮；装备、放入背包、放弃、卸下和替换均是可聚焦按钮。覆盖层打开时聚焦第一张候选卡，确认操作后聚焦下一步主按钮。

## 5. 容错与边界

- 背包已满且玩家选择“放入背包”时，提示“背包已满”，保留“装备 / 放弃”选项。
- 装备槽已满且玩家选择“装备”时，进入替换，不自动覆盖旧饰品。
- 候选饰品已拥有时不重复生成；如果可选池不足，使用未拥有的低品质饰品补足三张。
- 玩家可以放弃每日饰品，但仍然可以继续下一天；第三天放弃后直接进入结局。
- 刷新页面只重置内存状态，不保留饰品。
- 旧单晚模式不显示值班抽屉和三日数据，但原有反馈和结局保持不变。
- 所有新增文案必须在移动端换行，不得依赖 hover 才能理解规则。

## 6. 测试验收

在现有 Node test runner + Playwright 测试上增加：

1. 对话栏在进入、选择商品、提交后分别显示不同内容。
2. 商品标签和未覆盖需求会随选择实时变化。
3. 提交后能看到显性需求、隐藏需求、分数、连击和触发饰品。
4. 候选饰品可以选择“装备 / 放入背包 / 放弃”。
5. 装备满时可替换，取消替换不会改变原装备。
6. 可卸下已装备饰品，装备槽计数同步更新。
7. 背包达到 8 件后不能继续存入，仍可装备或放弃。
8. 协同只对已装备饰品生效，未装备饰品不触发。
9. 320px、390px 和桌面宽度下对话栏与饰品抽屉无横向溢出。
10. 旧单晚模式、离线检查、音频降级和键盘焦点测试继续通过。

## 7. 不扩大范围

- 不增加永久存档、货币、商店或联网功能。
- 不增加第三方运行时依赖。
- 不重写已有 SVG 场景和三日随机规则。
- 不增加新的结局，只让已有结局更好地反映饰品协同与本轮反馈。
