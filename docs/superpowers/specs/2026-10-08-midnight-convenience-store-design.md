# 《凌晨 2:17 的便利店》设计规格

**日期：** 2026-10-08
**状态：** 已获用户确认，待进入实现计划
**交付形式：** 单个可直接打开的 HTML 文件

## 1. 目标

制作一个 3～5 分钟完成一轮的叙事型微型游戏。玩家扮演深夜便利店店员，根据顾客的只言片语和状态，为他们挑选一袋“能让今晚继续下去的东西”。

作品需要同时体现：

- 统一、可辨识的视觉审美
- 清晰且有趣的核心交互
- 轻量但完整的叙事反馈
- 使用 Vibe Coding 快速迭代和打磨的能力
- 单文件、无后端、可直接分享的交付能力

## 2. 体验定位

整体风格为“荧光绿夜班”：

- 深墨绿作为主背景
- 荧光绿作为灯光和主要强调色
- 暖白作为文字和商品高光
- 少量珊瑚红用于警示、顾客反馈和情绪变化

视觉感觉应当安静、克制、略带温柔，不做复杂经营模拟，也不追求高强度挑战。

## 3. 核心玩法

每位顾客经历一轮相同的交互流程：

1. 顾客进入便利店。
2. 玩家阅读顾客台词和状态。
3. 玩家从货架中选择 3 件商品。
4. 玩家点击“装袋”提交选择。
5. 顾客产生反馈，灯光、环境或音效发生变化。
6. 记录本轮小票，进入下一位顾客。

游戏包含 3 位顾客。每位顾客都有多个“合理选择”，不要求玩家猜唯一正确答案。选择会影响顾客反馈和最终结局。

## 4. 顾客和商品内容

### 顾客一：阿成，外卖员

台词：

> 还有一单。手有点冷。

潜在需求：提神、补充能量、取暖。

### 顾客二：小雨，学生

台词：

> 我不饿，只想买点能带走的光。

潜在需求：陪伴、安心、微弱的希望感。

### 顾客三：没有名字的人

台词：

> 雨停了我就走。

潜在需求：避雨、陪伴、让等待变得舒服。

### 商品池

第一版至少包含 9 件商品，建议包括：

- 热咖啡
- 蜂蜜牛奶
- 能量棒
- 暖手贴
- 口香糖
- 杂志
- 小雨伞
- 电池
- 热食

商品需要带有内部标签，用于计算反馈，例如：

```text
warmth
energy
company
light
comfort
practical
```

这些标签不直接暴露给玩家，玩家通过顾客台词、视觉提示和反馈进行推断。

## 5. 结局设计

根据三轮选择的综合结果，进入至少三种结局：

- **今晚的灯一直亮着**：整体选择与顾客需求高度契合。
- **雨停了，但店里还有人**：选择有帮助，但仍留下未解决的情绪。
- **打烊之前，请再坐一会儿**：选择偏离需求，或玩家没有形成稳定的照顾方向。

结局页面包含：

- 结局标题
- 一段 2～4 行的短文案
- 三轮小票摘要
- “再来一晚”按钮

## 6. 页面和响应式布局

### 桌面端

- 顶部：时间 `02:17`、当前顾客编号、静音按钮
- 左侧约 60%：便利店场景、顾客、货架灯光
- 右侧约 40%：顾客信息、台词、购物袋
- 底部或场景前景：商品选择区和“装袋”按钮

### 移动端

垂直排列：

1. 顾客场景
2. 顾客台词
3. 商品网格
4. 当前购物袋
5. 提交按钮

所有按钮、商品卡片和文字必须在窄屏下不重叠、不溢出，商品卡片保持稳定尺寸。

## 7. 视觉反馈和动效

商品选择：

- 商品出现荧光描边
- 购物袋新增商品图标
- 货架灯光轻微闪烁

提交反馈：

- 顾客姿态或表情改变
- 背景灯光改变
- 出现简短反馈文字
- 生成一条夜班小票记录

动效应当服务于反馈和氛围，避免连续自动播放的大量动画影响可读性。

## 8. 技术边界

### 单文件要求

- 最终交付为一个 `.html` 文件。
- HTML、CSS、JavaScript 全部内嵌。
- 不依赖 CDN、后端、数据库或远程 API。
- 不依赖外部图片或外部字体。
- 商品图标使用 CSS 图形或内嵌 SVG。

### 状态和代码结构

使用一个集中管理的状态对象：

```text
intro
customer-1
customer-2
customer-3
ending
```

顾客、商品、反馈、结局均采用数据数组驱动。渲染和状态切换保持明确边界，避免把所有逻辑堆在点击处理器中。

### 音效

- 使用 Web Audio API 合成轻量环境声、按钮声和收银声。
- 默认静音或等待用户主动开启，避免浏览器自动播放限制。
- 即使音频不可用，游戏核心流程也必须完整可玩。

## 9. 可访问性和容错

- 商品和按钮使用真实的 `<button>` 或可访问交互元素。
- 选择状态有颜色以外的视觉提示。
- 支持鼠标、触摸和基础键盘操作。
- 文案和背景保持足够对比度。
- 音频初始化失败不能阻塞游戏。
- 游戏重新开始时清空上一轮状态。

## 10. 明确不做的内容

第一版不包含：

- 金币、库存、升级等经营系统
- 登录、排行榜和联网存档
- 在线 AI 对话
- 复杂 3D 场景
- 大量支线剧情
- 依赖第三方服务的动态内容

## 11. 验收标准

完成时必须满足：

1. 直接打开 HTML 文件即可进入游戏。
2. 首屏 10 秒内能理解基本目标。
3. 玩家可以完成 3 位顾客的完整流程。
4. 每轮可以选择 3 件商品并提交。
5. 至少存在 3 种可达结局。
6. 可以重新开始，且状态不会残留。
7. 静音功能可用，音频不可用时不影响玩法。
8. 桌面端和移动端布局均无明显重叠或溢出。
9. 页面不发起外部网络请求。
10. 最终文件可以作为单一链接或附件交付。

## 12. 开发阶段

### 阶段一：页面骨架

- 建立单文件结构
- 完成视觉变量和基础布局
- 完成开始界面和场景容器

### 阶段二：核心玩法

- 加入顾客数据和商品数据
- 完成选择、购物袋和提交逻辑
- 完成基础反馈

### 阶段三：结局和氛围

- 加入综合评分和结局判定
- 加入小票记录
- 加入灯光、粒子和轻量音效

### 阶段四：交付打磨

- 响应式适配
- 键盘和触摸验证
- 离线加载验证
- 单 HTML 完整性检查
- 生成最终分享文件
